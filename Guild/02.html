Về bài lab này
Dựng một llama.cpp server trên laptop của bạn, đo TTFT/TPOT/P50–P99, đẩy server tới điểm bão hoà, chứng minh continuous batching và giải thích một thay đổi tạo speedup thật trên chính máy bạn.

Bạn làm được gì sau bài này

  • Đo và báo riêng TTFT (prefill) và TPOT (decode) với P50/P95/P99 cho hai mức quantization.
  • Tìm thread count tốt nhất cho máy bạn và giải thích knee của đường cong bằng cơ chế cụ thể.
  • Chạy llama-server OpenAI-compatible, load test ở 10 và 50 user, và chứng minh continuous batching bằng /metrics.
  • Xác định điểm bão hoà bằng Little's Law và lập luận goodput@SLO.
  • Chạy RAG pipeline gọi vào server và chỉ ra stage chiếm nhiều latency nhất.

Cần chuẩn bị

  • Python 3.10 trở lên đã có trên máy.
  • RAM ≥ 8 GB cho Gemma 4 E2B, hoặc ≥ 4 GB cho Qwen3.5 0.8B; dưới 4 GB dùng Colab/Kaggle.
  • 3–10 GB đĩa trống và mạng truy cập được GitHub và Hugging Face.
  • Tài khoản GitHub để fork repo đề bài — bản fork chính là repo nộp bài.
  • Git
  • Python ≥ 3.10
  • Terminal: PowerShell trên Windows, hoặc shell có make trên macOS/Linux
Lỗi thường gặp
  • unknown model architecture: 'gemma4' → llama.cpp quá cũ; chạy make runtime (Windows: .\lab.ps1 runtime) để tải lại bản đã pin.
  • couldn't bind HTTP server socket … port: 8080 → port bị chiếm; đặt LAB_SERVER_PORT=8090 và dùng cùng biến đó cho smoke, load, metrics, pipeline.
  • make serve báo không tìm thấy venv → chưa chạy make setup.
  • busy_slots ≈ 1 trong report metrics → make metrics chạy khi server rảnh; chạy lại chồng thời gian với make load-50.
  • make metrics báo scrape failed → server chưa chạy; bật make serve trước.
  • Hugging Face bị chặn → làm theo docs/MANUAL-DOWNLOAD.md.
  • make: *** [verify] Error 1 sau checklist → make chỉ báo verify còn mục thiếu; đọc checklist phía trên.

Đây là bài cá nhân. Bạn làm trên máy của mình và tự nộp một repo riêng. Đầu ra cuối cùng là một repo GitHub public, trong đó có số đo latency, kết quả load test, bằng chứng continuous batching, kết quả RAG pipeline và bản submission/REFLECTION.md giải thích các con số đó.

Số liệu của bạn không so sánh được với bạn cùng lớp. Rubric chấm độ rõ ràng của setup, phép đo và lập luận, không chấm tốc độ tuyệt đối. Một laptop CPU 8 GB và một máy có GPU mạnh đều có thể đạt 100/100. Toàn bộ 100 điểm base không cần GPU, compiler hay Docker.

Fork repo đề bài và đặt tên bài nộp

Bạn không làm trực tiếp trên repo đề bài. Bạn fork nó về tài khoản GitHub của mình, và bản fork đó chính là repo bạn nộp. Vì vậy hãy đặt đúng tên bài nộp ngay từ lúc fork.

Repo đề bài Day 20
git clone https://github.com/VinUni-AI20k/K4-Track02-Day20-ModelServing-Lab.git
  • 1. Mở repo đề bài ở trên, bấm Fork ở góc trên bên phải.
  • 2. Ở trang Create a new fork, chọn Owner là tài khoản của bạn. Ô Repository name đổi thành tên theo mẫu K4-L3-DAY20-HoVaTen-MSSV-ModelServing: họ tên không dấu, không khoảng trắng, ví dụ K4-L3-DAY20-NguyenVanAn-20241234-ModelServing.
  • 3. Bấm Create fork. Bản fork của một repo public cũng là public — đúng yêu cầu nộp bài.
  • 4. Clone bản fork của bạn (không phải repo đề bài) về máy. Fork chỉ tạo bản sao trên GitHub, còn lab chạy trên laptop nên bạn cần code ở máy; mọi kết quả sau đó sẽ được git push ngược lên chính bản fork này. Clone rồi mở terminal ở thư mục gốc:
git clone https://github.com/<tài-khoản-của-bạn>/K4-L3-DAY20-<HoVaTen>-<MSSV>-ModelServing.git
cd K4-L3-DAY20-<HoVaTen>-<MSSV>-ModelServing

Nếu lỡ fork với tên mặc định, vào Settings → General → Repository name của bản fork để đổi tên, rồi clone theo tên mới. Kiểm tra bằng git remote -v: origin phải trỏ tới repo trên tài khoản của bạn, để mọi lần git push sau này đi thẳng vào bài nộp.

Lệnh make hay .\lab.ps1?

Mọi bước trong lab đều là một target có tên, ví dụ bench, serve, verify. Trên macOS/Linux bạn gõ make <target>. Windows không có make, nên repo kèm sẵn lab.ps1 với đúng các tên target đó: bạn gõ .\lab.ps1 <target>. Từ đây trở đi, khi thấy make bench, người dùng Windows hiểu là .\lab.ps1 bench.

Lab không dùng python toàn cục. Mọi thứ chạy trong virtualenv .venv mà bước setup tạo ra. Khi cần gọi Python trực tiếp, dùng .venv/bin/python (macOS/Linux) hoặc .venv\Scripts\python (Windows).

Setup: probe phần cứng, tải runtime và model

Trước khi đo bất cứ thứ gì, lab cần biết máy bạn có gì: bao nhiêu core, bao nhiêu RAM, có accelerator hay không. Mọi script phía sau đọc thông tin này để chọn số thread mặc định và quyết định có offload lên GPU hay không. Vì vậy bước đầu tiên là probe, và nó chạy được trước cả khi cài package nào.

Probe phần cứng

make probe

Lệnh này in CPU, số core physical/logical, RAM, accelerator và ghi ra hardware.json (rubric 1). Chụp màn hình ngay: submission/screenshots/01-hardware-probe.png.

Dựa vào RAM vừa thấy, chọn cách chạy:

RAMCách làm
≥ 8 GBDùng model mặc định Gemma 4 E2B (~5.2 GB tải về)
4–8 GBChạy local với Qwen3.5 0.8B (~0.9 GB tải về) — không mất điểm
< 4 GBLàm trên Colab/Kaggle theo docs/CLOUD.md — không mất điểm, nhưng phải khai báo ở REFLECTION §1

Rubric không quan tâm bạn chọn model nào. Model nhỏ còn giúp phần load test dễ đọc hơn, vì mỗi request xong nhanh hơn nên bạn thu được nhiều mẫu hơn trong 60 giây.

Cài đặt

Bước setup tạo .venv, cài 4 package Python, tải llama.cpp prebuilt binary (không compile) và tải hai mức quantization của model đã chọn. Mất khoảng 5–15 phút. Nếu chọn Qwen3.5 0.8B, đặt biến LAB_MODEL trước khi chạy setup.

Chọn lệnh setup theo hệ điều hành

make setup                              # Gemma 4 E2B (mặc định)
# hoặc, với RAM 4–8 GB:
LAB_MODEL=qwen35-0.8b make setup

Khi xong, models/active.json ghi lại model bạn đã chọn (rubric 2), nên các bước sau tự dùng đúng model mà không cần đặt lại biến. File weights (models/*.gguf) và binary (runtime/) đã nằm trong .gitignore; bạn không commit chúng.

Nếu tải model thất bại vì mạng chặn Hugging Face, script in ra đúng lệnh curl cần chạy; hướng dẫn tải tay ở docs/MANUAL-DOWNLOAD.md.

Checkpoint: bạn có hardware.json và models/active.json ở thư mục gốc repo, và terminal kết thúc bằng phần "Setup complete" cùng gợi ý lệnh tiếp theo. Hai file này là toàn bộ bằng chứng cho phần Setup (10 điểm); từ đây bạn đã có server và model để bắt đầu đo.
